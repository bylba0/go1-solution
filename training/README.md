# training — обучение RL-политики ходьбы (T3)

Здесь лежат код и конфигурации обучения, журналы прогонов, контрольные точки и результаты оценки. Это доказательство
самостоятельного обучения (ТЗ T3, п. 5.4).

## Что за политика

Это **остаточная RL-политика поверх опорной походки**. Цель суставам складывается из трёх частей:
`стойка + опорная рысь + 0,25/0,5/0,5 · a`, где `a` — выход сети.

Опорная рысь задана формулой (`env.gait_reference`):
- частота 2 Гц;
- диагональные пары ног FR+RL и FL+RR ходят в противофазе;
- размах бедра считается из заданной скорости;
- голень подъёма стопы — 0,35 рад в фазе переноса.

Политика, обученная PPO, добавляет к этой опоре поправку. Обучение даёт скорость, прямолинейность и устойчивость — сравнение
с опорой без поправки ниже.

Остальные блоки цели:
- **Область целей.** Цель обрезается по прямоугольнику, где у робота нет самоударов (`env.HIP/THIGH/CALF`).
- **Предел шага.** Цель меняется не больше чем на 4,3° на сустав между соседними командами 200 Гц.
- **Исполнение.** Политика работает на 50 Гц, только на numpy: `src/go1_walk/go1_walk/controller.py`.

## Среда (`env.py`)

- **Физика как у симулятора соревнования.** Та же сцена MuJoCo 3.3.7, шаг 2 мс. Закон моторов
  `tau = clip(kp·(q* − q) + kd·(0 − dq), пределы)` считается перед каждым шагом физики. Старт — из стойки узла симулятора.
  Траектория совпадает с циклом узла побитно: тест `test_trajectory_matches_simulator_node`.
- **Наблюдения актора** — то, что есть в `/lowstate`, за 3 последних кадра: гироскоп, вектор гравитации из кватерниона,
  `q − q0`, `dq`, прошлое действие, команда `(vx, vy, wz)`, фаза опоры.
- **Наблюдения критика** — те же плюс истинная скорость, высота, контакты стоп, параметры рандомизации.
- **Рандомизация:** трение стоп, масса корпуса, kp/kd ±10 %, толчки, шум наблюдений, задержка команд 0–10 мс. По флагам
  доступны ещё пачки физики без приёма команд и пропуски наблюдений.
- **Награды** (масштабы — в конфигурации):
  - поощряется следование скорости `vx, vy` и угловой скорости `wz`, поза, время стопы в воздухе;
  - штрафуется вертикальная скорость, угловая скорость по x/y, наклон, моменты, энергия, резкость действий, стояние
    не в позе при нулевой команде, скольжение и высота подъёма стоп, падение.

  Это набор наград Go1 Joystick из MuJoCo Playground.
- **Завершение эпизода:** высота корпуса < 0,18 м, крен или тангаж > 45°, контакт робота с самим собой, предел 20 с.

## PPO (`ppo.py`, `train.py`)

- Актор и критик — MLP 512-256-128 с ELU; критик асимметричный (видит больше актора).
- GAE γ = 0,99, λ = 0,95; обрезка 0,2.
- Адаптивный шаг обучения по KL, цель 0,01.
- Сбор опыта — в N процессах по 32 среды, 24 шага за итерацию. Обновление — на CPU или GPU (`--device`).

Каталог прогона `--out` содержит:
- `config.json`;
- `run.json` — сид, версии пакетов, ОС, устройство, ревизия кода;
- `curve.csv` — итерация, шаги, время, возврат, длина эпизода, ошибка скорости, доли падений и самоударов, KL, шаг, разброс;
- контрольные точки `checkpoints/*.pt` и их суммы `checkpoints/sha256.txt`;
- `policy.npz` и `policy.npz.sha256`.

Журнал — это стандартный вывод `train.py`, сохраняется через `tee` (см. ниже). В `logs/<прогон>/` эти файлы лежат
под именами `train.log` и `checkpoints.sha256`.

Ревизия кода в `run.json` и в этом файле — идентификатор версии в рабочем репозитории разработки. История этого
репозитория в сдачу не входит. Воспроизведение делается текущим кодом `training/`.

## Как запустить

```
pip install -r training/requirements.txt                                   # mujoco 3.3.7, numpy 1.26.4, torch, pytest
export GO1_MODEL_DIR=<simulator>/models/mujoco/unitree_go1                 # каталог модели со scene.xml
export GO1_SIM_DIR=<simulator>                                             # корень симулятора: сверка с законом его узла
python -m pytest -q training/tests        # без GO1_MODEL_DIR тесты среды пропускаются, без GO1_SIM_DIR — 4 теста сверки
python -m training.train --config training/configs/walk_trot.json --out training/runs/<имя> \
    --workers <N> --seed <сид> [--iterations <K>] [--minutes <M>] [--device cpu|cuda] | tee training/runs/<имя>.log
python -m training.export training/runs/<имя>/checkpoints/<точка>.pt policy.npz   # веса для go1_walk, sha256 рядом
```

Правила оценки эпизода, по которым получены все `evaluation.json`, — `episode_rules.py`. Если коротко: прогрев 1,5 с, затем
90 с; успех — 3 м вперёд по курсу конца прогрева без падения за эпизод. Падение — высота корпуса < 0,16 м или |крен|/|тангаж|
> 50°, непрерывно дольше 0,5 с.
